# Languages

Joran separates two things:

- the **language of a text**: each post or page says it with `lang:` in its front matter. Any language works;
- the **language of the interface** (menus, buttons, dates, the terminal): chosen from `languages` in `site.config.js`. Dictionaries exist for **English and French** (`theme/i18n/`); you can add any other language yourself.

## A site in one language

```js
languages: ["fr"],
```

The whole interface is in French. You can still write some posts in English (`lang: en`): they are marked *EN* in lists, and the journal gets a language filter.

## Switching a language on or off

It is one line in `site.config.js`:

```js
languages: ["en"],         // off: one language
languages: ["en", "fr"],   // on: English at the root, French under /fr/
```

When a language is off, its folder (`content/fr/`) is simply ignored: keep it for later or delete it. Posts in that language stay published (they are posts, wherever their language), with the main interface language around them.

Two interface languages mean maintaining two versions of your pages (home, Now, Uses…). If you only want some posts in another language, you do not need it: keep one language and set `lang:` on those posts.

## A site in two languages

```js
languages: ["en", "fr"],
```

- The first language is the main one: its pages are at the root (`/`, `/journal/`, `/tags/`).
- Every other language gets its own **journal** and **tags** pages (`/fr/journal/`, `/fr/tags/`), generated automatically, and a **language switch** in the sidebar.
- Create a **home page** for each extra language: `content/fr/index.md` (with `lang: fr` and `layout: home`).
- Other pages in that language go in the same folder: `content/fr/a-propos.md` → `/fr/a-propos/`. Give each page `lang: fr`, or put a `content/fr/fr.json` file containing `{ "lang": "fr" }` to set it for the whole folder.
- A post in French (`lang: fr`) is shown with the French interface, wherever it lives.
- Menu links follow the visitor: on a French page, `/journal/` points to `/fr/journal/`, and `/now/` points to `/fr/now/` if that page exists.

## Translations of the same text

Give the same `translationKey` to the versions of a post or page:

```yaml
# content/posts/2026-11-15-welcome.md
lang: en
translationKey: welcome
```

```yaml
# content/posts/2026-11-15-bienvenue.md
lang: fr
translationKey: welcome
```

Then:

- each version links to the others ("Also in: …");
- the language switch goes straight to the translation instead of the home page;
- search engines get `<link rel="alternate" hreflang="…">` for each version.

## Changing an interface text

Create `content/i18n/<lang>.json` with only the keys you want to change. They are merged over the theme's dictionary, and survive theme updates:

```json
{
  "nav": { "journal": "Blog" },
  "home": { "featured": "Things I made" }
}
```

All keys are in `theme/i18n/en.json`.

## Another language than English or French

The two languages of your site can be any pair, e.g. French and Spanish:

1. Copy `theme/i18n/en.json` to `content/i18n/es.json` and translate the values. Keep the keys, the `{placeholders}` and the HTML tags.
2. Set the languages: `languages: ["fr", "es"]`.
3. Optionally, set the date format: `locales: { es: "es-ES" }`.

Your dictionary lives in `content/`, so theme updates never overwrite it.

## Right-to-left languages

Not supported yet. The layout uses logical CSS properties (`margin-inline`, `inset-inline`), so `dir="rtl"` support is on the roadmap.
